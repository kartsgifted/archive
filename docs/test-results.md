## 4.5 기기별 확인 — 2026-09-23 · 6/7 확인, 1종 확인 불가

**방법**: 엔진 3종(Chromium · WebKit · Firefox) × 화면 크기별로 로그인 → 분야 선택 → 프로그램 선택 → 일정표 → 검색을 돌며 JS 오류·가로 스크롤·레이아웃 넘침을 확인. 화면마다 스크린샷 촬영.

> WebKit은 Playwright가 제공하는 Safari 엔진 빌드다. 실제 iPhone Safari와 완전히 같지는 않으므로, 실기기 확인을 대체하지는 않는다.

### 발견 — 모바일 입력창 글자 크기

| 입력창 | 크기 | 영향 |
|---|---|---|
| `code-input` | 18px | 문제 없음 |
| `name-input` | 15px | **iOS Safari에서 초점이 가면 화면이 확대된다** |
| `search-input` | 14px | 위와 같음 |

iOS Safari는 글자 크기가 16px 미만인 입력창에 초점이 가면 화면을 자동으로 확대한다. 확대된 뒤에는 저절로 돌아오지 않아 이용자가 손으로 축소해야 한다. 모바일에서만 16px 이상으로 두면 해결된다(`viewport`에 `maximum-scale`을 넣어 막는 방법은 확대 자체를 막아 접근성을 해치므로 쓰지 않는다).

> 이 환경에서는 실제 iOS 기기가 없어 **증상을 재현하지 못했다.** 글자 크기 값과 알려진 동작에 근거한 판단이므로, 실기기에서 한 번 확인할 것.

### Firefox — 확인 불가

이 PC의 Firefox가 `kartsgifted.github.io`에 연결되지 않는다(`NS_ERROR_NET_TIMEOUT`).

- 같은 Firefox로 `example.com`은 정상 접속된다 → Firefox 자체나 일반 통신 문제는 아니다
- IPv6·HTTP/3를 각각 끄고 네 가지 조합으로 재시도했으나 모두 동일했다
- 같은 PC의 Chromium·WebKit은 정상 접속된다

**이 PC의 통신 환경 문제로 보이나 확정하지 못했다.** 실제 Firefox로 사이트를 열어보면 1분 안에 판별된다. 사이트 결함으로 단정하지 말 것.

### 오탐 2건 (점검 중 잘못 잡았다가 확인한 것)

| 처음 신호 | 실제 |
|---|---|
| 모바일 일정표에서 표가 화면 밖으로 넘침 | **정상 설계.** 표를 `min-width: 520px`로 두고 가로 스크롤 컨테이너에 담아 "← 표를 옆으로 밀어 보세요" 안내까지 띄운다. 문서 전체가 가로로 밀리지는 않는다(가로 스크롤 0px) |
| WebKit에서 CSP가 스타일시트를 거부 | **점검 도구가 유발.** Playwright가 스크린샷을 찍을 때 페이지에 스타일을 주입하는데 CSP가 이를 막은 것이다. 스크린샷을 찍지 않으면 전 화면에서 오류 0건이고, 스타일시트는 9+185 규칙이 모두 적용된다. 오히려 **CSP가 의도대로 작동한다는 증거** |
