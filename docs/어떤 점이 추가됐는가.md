# 예전 워크숍 아카이브와 새 아카이브 비교

> 대상: 예전 워크숍 아카이브를 만든 담당자 및 보고 대상
> 근거: 저장소 루트의 `index.html`·`data.json`(예전 사이트), `site/`·`apps-script/`(새 사이트), `docs/architecture.md`

---

## 1. 한 줄 요약

예전 사이트는 **자료를 화면 파일 안에 담아두고 코드로 가려놓은 방식**이고,
새 사이트는 **화면에 자료를 두지 않고 요청할 때마다 관문이 검사해서 내보내는 방식**이다.

---

## 2. 가장 큰 차이 — 자료와 접속코드의 위치

| 항목 | 예전 사이트 | 새 사이트 |
|---|---|---|
| 자료 보관 | `data.json` 파일 하나에 일정·영상이 모두 들어 있음 | 화면에는 자료가 없음. 구글 시트에 있고 관문이 꺼내 줌 |
| 접속코드 | 같은 `data.json` 안에 그대로 적혀 있음 | 시트 「코드」 탭에만 있음. 화면 코드에는 없음 |
| 코드 확인 | 브라우저 화면 스크립트가 문자열을 비교 | 관문(Apps Script)이 서버에서 확인하고 서명된 토큰을 발급 |
| 실질적 차이 | 주소를 아는 사람이 데이터 파일을 직접 열면 코드 없이도 내용이 보임 | 코드 없이는 어떤 자료도 나오지 않음. 요청마다 다시 확인 |

이것이 재구축의 핵심 이유이며, 아래 항목들은 여기서 파생된 변화다.

---

## 3. 자료를 바꾸는 방법

| | 예전 사이트 | 새 사이트 |
|---|---|---|
| 방법 | `data.json` 파일을 직접 고쳐 다시 올림 | 시트에 행을 추가하고 공개여부를 `공개`로 바꿈 |
| 담당 | 개발자를 거쳐야 함 | 운영진이 직접 |
| 검수 | 별도 장치 없음 | 자료는 기본값이 `검수대기`. `공개`로 바꾸기 전에는 나가지 않음 |

탭별로 화면에 반영되는 시점이 다르다 — `docs/sheet-schema.md` 12절 참조.

---

## 4. 다루는 범위

| | 예전 사이트 | 새 사이트 |
|---|---|---|
| 프로그램 | 워크숍 | 워크숍 · 심화 멘토링 · 겨울 심화캠프 |
| 자료 종류 | 영상 | 영상 · 사진 · 사진묶음 · 학생 작품(영상·이미지) |
| 일정표 형태 | 일자 × 시간대 격자 | 워크숍은 일자 × 시간대, 멘토링은 권역 × 회차, 캠프는 일자별 카드 |

---

## 5. 화면 흐름

| | 예전 사이트 | 새 사이트 |
|---|---|---|
| 단계 | 분야 → 일정표 → 영상 보기 (+ 검색 결과) | 로그인 → 분야 → 프로그램 → 일정표 → 자료 목록·열람 → 검색·인물 상세 |

---

## 6. 로그인

| 항목 | 예전 사이트 | 새 사이트 |
|---|---|---|
| 코드 | 공용 1개 | 5종 (운영진 1 + 분야별 4) |
| 입력 | 코드만 | 코드 + 이름 |
| 접속 유지 | 브라우저에 "통과함" 표시만 남김 | 관문이 발급한 서명 토큰. 만료·연장 처리 |
| 보호 장치 | 없음 | 입력 실패 제한, 접속 기록(「로그」 탭), 코드 버전을 올리면 해당 코드의 접속이 즉시 해제됨 |
| 열람 범위 | 전체 | 전체. 코드에 따라 로그인 직후 첫 화면만 달라짐 |

---

## 7. 검색

| | 예전 사이트 | 새 사이트 |
|---|---|---|
| 결과 | 학생 이름으로 영상 목록 | 이름으로 찾으면 그 학생의 인물 상세(참여한 클래스 + 그 학생의 작품)로 이동 |
| 동명이인 | 구분 없음 (이력이 한 명으로 합쳐짐) | 「학생」 탭의 학생ID로 구분해 목록에서 선택 |

---

## 8. 그대로 이어받은 것

예전 사이트의 형태를 유지하고 그 위에 보안 구조와 범위를 얹었다.

- 디자인 톤 (잉크·골드·크림 색, 모서리 브라켓 모티프)
- 일정표 격자 형태와 칸 구성
- 영상 볼 때 옆에 목록이 함께 뜨는 구조
- 한글 자판 상태로 코드를 입력해도 인식되는 기능
- 로그인 화면 배경 사진
- 학생 이름 검색

## 9. 아직 남은 것

| 항목 | 내용 |
|---|---|
| 프로그램 대표 사진 | 프로그램 선택 화면 카드에 넣을 워크숍 · 심화 멘토링 · 겨울 심화캠프 사진 3장이 필요하다. 현재는 분야 사진으로 임시로 채워 둠 |
| 공개 주소 배포 | `site/` 폴더만 게시해야 한다. 저장소 루트(예전 사이트 파일)와 `docs/`가 함께 공개되면 안 되므로, GitHub Pages 기본 설정(루트 또는 `/docs` 게시) 대신 `site/`만 올리는 배포 설정이 필요하다. 아직 만들지 않음 |
| 영상 도메인 등록 | 공개 주소가 정해지면 Vimeo 허용 도메인에 등록해야 영상이 재생된다 |
| 「일정」 탭 검수 | 「자료」와 달리 「일정」 탭에는 공개여부 열이 없어 입력하는 즉시 화면에 나간다. 검수 전 일정을 가릴 필요가 있는지 **확인 필요** |
