# 자료 관리 시트 명세

> Google Sheets **4개**(공통 1 + 프로그램별 3). 공유하지 않으며 관문을 통해서만 접근한다.
> 2026-09-18 개정: 한 시트(9개 탭)에서 프로그램별 시트로 나눔. 이유는 `docs/decisions.md` 5절 참조.

---

## 1. 확정 사항

| 항목 | 규칙 |
|---|---|
| 시트 | **공통** · **워크숍** · **심화 멘토링** · **겨울 심화캠프** (4개) |
| 공통 시트 탭 | 읽어보기 · 학생 · 접근코드 · 설정 · 로그 |
| 프로그램 시트 탭 | 읽어보기 · 일정 · 자료 · 출석부 · 참여자 (세 시트 모두 같은 구성) |
| 프로그램 구분 | **어느 시트에 있느냐로 정한다.** 행마다 프로그램을 적지 않는다 |
| 학생ID | 동명이인 구분용. 공통 시트 「학생」 탭에서 수기로 순번 부여(`ST-0001`), 프로그램 시트의 「출석부」·「자료」 탭에 기재 |
| 세션ID | 자동 생성 (직접 입력 금지). 사업연도·프로그램을 앞에 붙임 (`26-ws-music-0807-1`) |
| 공개여부 | 검수대기(기본) / 공개 / 비공개 |
| 자료 유형 | 영상 · 사진 · 사진묶음 · 작품(영상) · 작품(이미지) |
| 묶는 기준 | 워크숍 일자×시간 / 멘토링 분야×권역×회차 / 캠프 일자 |
| 접근코드 | `KA-MUSIC-7Q4F` 형식, 5종, 모두 전체 열람 |
| 파일명 | `20261015_1330_음악_A.mp4` |
| 메뉴 | **공통 시트에만 있다.** 프로그램을 골라 세션ID 생성 · 출석부 변환 · 영상 매칭, 전체 점검 |

## 2. 시트·탭 구성

### 2-1. 시트

| 시트 | 탭 | 관문이 여는 방법 |
|---|---|---|
| 공통 | 읽어보기 · 학생 · 접근코드 · 설정 · 로그 | 관문 스크립트가 **붙어 있는** 시트. 따로 열 필요 없음 |
| 워크숍 | 읽어보기 · 일정 · 자료 · 출석부 · 참여자 | Script Properties에 둔 시트 ID로 연다 (14절) |
| 심화 멘토링 | 위와 같음 | 위와 같음 |
| 겨울 심화캠프 | 위와 같음 | 위와 같음 |

- 공통 시트에는 프로그램과 무관하게 **한 곳에만 있어야 하는 것**을 둔다. 학생ID는 프로그램이 달라도 같은 학생이면 같은 값이어야 하고, 접근코드·설정·로그는 사이트 전체에 하나다.
- 프로그램 시트 세 개는 **탭 이름과 열 구성이 모두 같다.** 관문과 메뉴가 같은 코드로 세 시트를 다룬다.
- **탭 이름은 함부로 바꾸지 않는다.** 관문은 탭을 이름으로 찾으므로, 위 표의 이름을 바꾸면 그 기능이 즉시 멈춘다. 2026-09-23에 「코드」를 「접근코드」로 바꿔 전체 로그인이 중단된 사례가 있다. 바꿔야 하면 관문 코드를 함께 고쳐 재배포해야 한다.

### 2-2. 탭

| 탭 | 위치 | 입력 | 역할 |
|---|---|---|---|
| 읽어보기 | 모든 시트 | 안내 | 입력 규칙과 자료 유형 설명 |
| 일정 | 프로그램 시트 | 직접 | 수업 한 칸이 한 줄. 세션ID는 자동 생성 |
| 자료 | 프로그램 시트 | 직접 | 영상·사진 한 건이 한 줄. 세션ID로 일정과 연결 |
| 출석부 | 프로그램 시트 | 직접 | 가로 수업 × 세로 성명. 동명이인은 학생ID도 같이 기재 |
| 참여자 | 프로그램 시트 | **자동** | 같은 시트의 출석부에서 변환. 성명 검색의 근거 |
| 학생 | 공통 | 직접 | 학생ID·성명 명부. 동명이인 구분의 근거 |
| 접근코드 | 공통 | 직접 | 접근코드·사용기한·버전 |
| 설정 | 공통 | 직접 | 사업연도, 영상 서비스, 안내 문구 등 운영 값 |
| 로그 | 공통 | **자동** | 로그인·자료 요청 기록 |

## 3. 탭별 열 구성

### 3-1. 읽어보기

표 형식 열 구성 없음. 자유 서식 안내문(입력 규칙, 자료 유형 설명, 예시)을 적는다.

### 3-2. 일정 (프로그램 시트)

수업 한 칸이 한 줄. 자동 생성·잠금 열은 별도 표기.

| 열 | 입력 | 비고 |
|---|---|---|
| 세션ID | 자동 · 잠금 | [세션ID 생성] 메뉴로 부여. 직접 입력 금지 |
| 분야 | 선택 목록 | 음악 · 무용 · 전통예술 · 미술 |
| 일자 | 직접 | |
| 시작시각 | 직접 | |
| 종료시각 | 직접 | 시작·종료 두 열로 분리(기존 코드의 EN DASH 전용 분리 방식은 가져오지 않음) |
| 권역 | 직접 | 심화 멘토링 시트만 사용 |
| 회차 | 직접 | 심화 멘토링 시트만 사용 |
| 수업명 | 직접 | 일정표·목록 화면 제목 |
| 강사명 | 직접 | 일정표·자료 상세에 담당 강사 표시용 |
| 비고 | 직접 | |

> 개정 전에 있던 **프로그램 열은 없앴다.** 시트가 곧 프로그램이므로, 열을 두면 시트와 다른 값이 적히는 실수만 생긴다. 관문이 어느 시트에서 읽었는지를 보고 응답의 `program` 값을 채운다(`docs/api.md` 3-3).
>
> 묶는 기준(워크숍=일자×시간대 / 멘토링=분야×권역×회차 / 캠프=일자)은 7절 참조.

### 3-3. 자료 (프로그램 시트)

영상·사진 한 건이 한 줄. 세션ID로 같은 시트의 「일정」과 연결한다.

| 열 | 입력 | 비고 |
|---|---|---|
| 세션ID | 직접 | 같은 시트 「일정」 탭 값 선택. **학생 작품은 비움** |
| 자료유형 | 선택 목록 | 영상 · 사진 · 사진묶음 · 작품(영상) · 작품(이미지) |
| 파일명 | 직접 | 영상은 `20261015_1330_음악_A.mp4` 규칙 적용. 로그 탭의 "대상 자료"는 이 값으로 식별 |
| 링크 | 직접 | Vimeo ID 또는 Drive 파일 ID |
| 공개여부 | 선택 목록 | 검수대기(기본) · 공개 · 비공개 |
| 규격 | 직접 | 사진묶음의 전체 장수 등 |
| 학생명 | 직접 | **작품(영상)·작품(이미지)일 때만 기재** |
| 학생ID | 직접 | **작품일 때만 기재.** 공통 시트 「학생」 탭에서 확인한 값(`ST-0001`). 동명이인 구분용, 13절 참조 |
| 분야 | 직접 | **작품일 때만 기재** (세션ID가 없어 일정에서 분야를 유추할 수 없음). 일반 자료는 세션ID로 분야를 알 수 있어 비움 |
| 비고 | 직접 | |

> **학생 작품을 어느 프로그램 시트에 적을지** — 작품이 만들어진 프로그램의 시트에 적는 것을 원칙으로 한다. 어느 프로그램에도 속하지 않는 작품이 있는지는 **확인 필요**.

### 3-4. 출석부 (프로그램 시트)

고정 열 구성이 아니라 **가로 = 수업, 세로 = 성명인 행렬**. 담당자가 기존에 쓰던 출석부 형태 그대로 입력하면 [출석부 변환] 메뉴가 **같은 시트의** 「참여자」 탭으로 바꾼다.

| 구성 | 내용 |
|---|---|
| 첫 행 | 수업(세션ID 또는 수업명) 나열. 같은 시트 「일정」에서 찾는다 |
| 첫 열 | 학생 성명 |
| 둘째 열 | 학생ID — **동명이인일 때만 기재**. 공통 시트 「학생」 탭에서 확인한 값(`ST-0001`). 처음 등장하는 학생은 [출석부 변환] 전에 「학생」 탭에 먼저 등록 |
| 교차 칸 | 출석 표시(예: 출석 시 체크, 결석 시 공란) |

- 출석부는 프로그램마다 따로 있다. 워크숍 출석부를 변환해도 **멘토링·캠프 참여자는 바뀌지 않는다.**
- 한 프로그램 안에서는 여전히 그 프로그램의 모든 분야·회차가 한 탭에 들어간다. 변환은 그 시트의 「참여자」 전체를 새로 쓴다.

> 정확한 표시 기호·양식은 기존에 쓰던 출석부 파일을 확인 후 맞춘다. **확인 필요**

### 3-5. 참여자 (프로그램 시트, 자동)

같은 시트의 「출석부」에서 변환되며 잠금. 성명 검색의 근거가 되는 탭이므로 (성명 × 참여 세션) 조합마다 한 줄.

| 열 | 비고 |
|---|---|
| 성명 | |
| 학생ID | 「출석부」에 값이 있으면 그대로 옮김. 없으면 빈 칸(동명이인이 없는 학생) |
| 세션ID | 같은 시트 「일정」 탭과 연결. 관문이 세 시트의 참여자를 합쳐 내보내고, 화면은 세션ID로 분야·프로그램·일자를 조인해 표시 |

### 3-6. 접근코드 (공통 시트)

| 열 | 비고 |
|---|---|
| 코드 | `KA-MUSIC-7Q4F` 형식 |
| 이름 | 배포 대상 설명용 라벨 |
| 배포 대상 | 운영진 · 분야별(음악/무용/전통예술/미술) |
| 첫 화면 | 로그인 직후 진입할 분야·화면 |
| 사용기한 | 운영진 2027-03-31 / 분야별 교강사 2027-02-28 |
| 상태 | 사용 · 정지 등 |
| 버전 | 값을 올리면 해당 코드의 모든 접속이 즉시 해제됨 |
| 비고 | |

### 3-7. 설정 (공통 시트)

고정 열이 아니라 **항목-값 구조**(키-값 표)로 운영 값을 담는다.

| 열 | 비고 |
|---|---|
| 항목 | 예: 사업연도, 영상서비스, 진입 안내문구, 외부유출 금지 안내문 등 |
| 값 | |
| 설명 | |

| 항목 | 값 예 | 쓰임 |
|---|---|---|
| 사업연도 | `2026` | [세션ID 생성]이 세션ID 앞 두 자리로 쓴다(7절). **사업연도는 달력 연도와 다를 수 있다** — 2027년 1월 겨울캠프도 2026 사업이면 `2026` |

### 3-8. 로그 (공통 시트, 자동)

관문이 기록하며 잠금.

| 열 | 비고 |
|---|---|
| 일시 | |
| 결과 | 성공 · 실패(사유) |
| 코드 | 사용한 접근코드 |
| 이름 | 입력한 이름 |
| 기기ID | `localStorage`에 저장된 값 |
| 요청 | 요청 종류 |
| 대상 자료 | 「자료」 탭의 파일명으로 식별 |

### 3-9. 학생 (공통 시트)

동명이인 구분의 근거가 되는 명부. 동명이인이 실제로 발견된 학생만 등록한다(전체 학생을 다 올릴 필요 없음). 13절 참조.

| 열 | 입력 | 비고 |
|---|---|---|
| 학생ID | 직접 | 수기로 다음 순번을 부여(`ST-0001`, `ST-0002` …). 자동 생성 아님 |
| 성명 | 직접 | |
| 비고 | 직접 | 담당자가 구분에 참고할 정보(예: 학교명). 화면에는 노출하지 않음 |

## 4. 선택 목록 (드롭다운)

고정값 항목에는 선택 목록을 적용한다. 표기가 흔들리면 화면에서 자료가 묶이지 않기 때문이다.

| 항목 | 목록 | 사용 탭 |
|---|---|---|
| 분야 | 음악 · 무용 · 전통예술 · 미술 | 일정 · 자료(작품) |
| 자료 유형 | 영상 · 사진 · 사진묶음 · 작품(영상) · 작품(이미지) | 자료 |
| 공개여부 | 검수대기 · 공개 · 비공개 | 자료 |
| 학생ID | 공통 시트 「학생」 탭의 학생ID 목록 | 출석부(동명이인만) · 자료(작품) |

> 개정 전의 **프로그램** 선택 목록은 열이 없어져 쓰지 않는다.
>
> **학생ID 선택 목록은 확인 필요.** 구글 시트의 선택 목록은 같은 시트 안의 범위만 참조할 수 있어, 공통 시트의 「학생」 탭을 프로그램 시트에서 바로 드롭다운으로 쓸 수 없다. 방법은 ① 프로그램 시트에 숨김 탭을 두고 `IMPORTRANGE`로 학생 명부를 가져와 참조, ② 드롭다운 없이 입력하고 [점검]이 「학생」 탭에 없는 ID를 찾아내는 것 두 가지다. 동명이인 발생 빈도가 낮아 **②를 기본으로 한다.**

## 5. 자료 유형

| 유형 | 내용 |
|---|---|
| 영상 | 수업 영상 |
| 사진 | 대표 사진 한 장. 화면에 직접 표시 |
| 사진묶음 | 전체 사진 폴더 링크. 규격 칸에 전체 장수 기재 |
| 작품(영상) | 학생 작품. 세션ID를 비우고 학생명과 분야를 기재. 동명이인이면 학생ID도 기재 |
| 작품(이미지) | 위와 같음 |

대표 사진은 한 수업당 5~8장만 화면에 직접 표시하고, 전체는 폴더로 연결한다.

> **확인 필요** — 구글 로그인을 쓰지 않기로 하여 전체 사진 폴더의 열람 방법이 아직 정해지지 않았다. (`docs/decisions.md` 9절)

## 6. 공개여부

| 값 | 의미 |
|---|---|
| 검수대기 | **기본값.** 행을 추가하면 이 상태가 된다 |
| 공개 | 사이트에 내보낸다. **관문은 이 값만 내보낸다** |
| 비공개 | 사이트에 내보내지 않는다 |

## 7. 세션ID

- 분야·일자·시간대를 입력하면 **자동 생성**된다 ([세션ID 생성] 메뉴, 10절).
- **직접 입력하지 않는다.** 수기 입력 시 오타 한 글자로 영상이 연결되지 않는다.
- 「자료」·「참여자」 탭은 세션ID로 같은 시트의 「일정」 탭과 연결된다.

**형식** — `{사업연도}-{프로그램코드}-{분야코드}-…`

| 코드 | 값 |
|---|---|
| 사업연도 | 공통 시트 「설정」 탭 `사업연도`의 뒤 두 자리 (`2026` → `26`) |
| 프로그램코드 | 워크숍 `ws` · 심화 멘토링 `mt` · 겨울 심화캠프 `camp` |
| 분야코드 | 음악 `music` · 무용 `dance` · 전통예술 `trad` · 미술 `art` |

| 프로그램 | 형식 | 예 |
|---|---|---|
| 워크숍 | `{연도}-ws-{분야코드}-{MMDD}-{순번}` | `26-ws-music-0807-1` |
| 심화 멘토링 | `{연도}-mt-{분야코드}-{권역}-{회차}` | `26-mt-music-광주-1` |
| 겨울 심화캠프 | `{연도}-camp-{분야코드}-{MMDD}-{순번}` | `26-camp-music-0115-1` |

- **사업연도를 넣는 이유**: 연도가 없으면 다음 해 같은 날짜(워크숍·캠프)나 같은 권역·회차(멘토링)에서 세션ID가 겹친다. 이 아카이브를 다음 해에도 쓰는지는 **확인 필요**지만, 한 해만 쓰더라도 손해가 없어 넣어 둔다.
- **달력 연도가 아니라 사업연도인 이유**: 겨울캠프는 2027년 1월에 열려도 2026 사업에 속한다. 일자에서 연도를 뽑으면 `27-`이 붙어 같은 사업의 자료가 갈라진다.
- **프로그램코드를 둘째 자리에 두는 이유**: 세션ID만 보고도 어느 프로그램 시트의 행인지 알 수 있다.
- 다음 사업연도가 시작되면 「설정」의 `사업연도`만 바꾼다. 이미 부여된 세션ID는 바뀌지 않는다.

이미 세션ID가 있는 행은 다시 만들지 않는다. 행을 지웠다 새로 추가하면 순번이 꼬일 수 있어 [점검] 메뉴로 중복을 확인한다.

### 묶는 기준

| 프로그램 | 기준 |
|---|---|
| 워크숍 | 일자 × 시간대 |
| 심화 멘토링 | 분야 × 권역 × 회차 |
| 겨울 심화캠프 | 일자 |
| 학생 작품 | 시간대에 귀속되지 않음. 학생 · 분야 단위 |

## 9. 영상 파일명 규칙

```
20261015_1330_음악_A.mp4
└─일자──┘ └시간┘ └분야┘ └카메라
```

- 향후 촬영분부터 적용한다.
- 기촬영분은 업로드 일시와 재생 시간을 대조해 초벌 연결한 뒤 검수한다.
- 파일명에는 프로그램이 없다. [영상 매칭]은 메뉴에서 고른 프로그램 시트 안에서만 일정을 찾는다.

## 10. 시트 메뉴

메뉴는 **공통 시트에만** 뜬다. 시트 메뉴는 스크립트가 붙어 있는 시트에만 나타나는데, 프로그램 시트마다 스크립트를 따로 붙이면 Apps Script 프로젝트가 4개로 늘어 배포·인수인계 관리가 어려워지기 때문이다.

```
K예술영재 아카이브
├─ 워크숍        ▸ 세션ID 생성 · 출석부 변환 · 영상 매칭
├─ 심화 멘토링   ▸ 세션ID 생성 · 출석부 변환 · 영상 매칭
├─ 겨울 심화캠프 ▸ 세션ID 생성 · 출석부 변환 · 영상 매칭
└─ 점검 (공통 시트와 세 프로그램 시트 전체)
```

| 메뉴 | 동작 |
|---|---|
| 세션ID 생성 | 고른 프로그램 시트의 「일정」 새 행에 세션ID를 부여한다 |
| 출석부 변환 | 고른 프로그램 시트의 「출석부」를 같은 시트 「참여자」로 변환한다 |
| 영상 매칭 | 고른 프로그램 시트 안에서 파일명 규칙으로 영상과 세션을 연결한다 |
| 점검 | 빠진 값·중복·연결 안 된 자료, 「학생」 탭에 없는 학생ID를 네 시트 전체에서 찾아낸다 |

> 담당자는 프로그램 시트에서 입력하고, 메뉴를 쓸 때만 공통 시트를 연다. 불편이 크면 프로그램 시트마다 메뉴를 붙이는 방식을 다시 검토한다.

## 12. 운영 순서와 반영 시점

```
행 추가 → [점검] → 검수 → 공개여부 "공개" (별도 버튼 없이 즉시 반영)
```

위 순서는 「자료」 탭 기준이다. **공개여부 열은 「자료」 탭에만 있고, 다른 탭은 걸러내지 않는다.**
관문(`apps-script/Data.js`)이 탭별로 다르게 처리하므로 반영 시점도 다르다. 프로그램 시트의 탭은 세 시트 모두 같은 규칙이다.

| 탭 | 화면 반영 | 비고 |
|---|---|---|
| 일정 | 입력하는 즉시 | 걸러내지 않는다. 검수 전 일정도 그대로 나간다 (`docs/decisions.md` 9절 확인 필요) |
| 자료 | 공개여부 `공개`인 행만 | `검수대기`·`비공개`는 나가지 않는다. 사진은 열어볼 때 한 번 더 확인한다 |
| 출석부 | **바로 반영되지 않는다** | 관문이 읽지 않는 탭이다. 해당 프로그램의 [출석부 변환]을 실행해 「참여자」가 갱신돼야 반영된다 |
| 참여자 | 즉시 | 변환 결과가 들어오면 그대로 나간다 |
| 학생 | 화면에 직접 반영되지 않는다 | 학생ID의 근거·[점검]용 명부 |
| 접근코드 | 즉시 | 버전을 올리면 해당 코드의 기존 접속이 해제된다 |
| 설정 | 즉시 | `사업연도`는 화면이 아니라 [세션ID 생성]에 쓰인다 |
| 로그 | — | 관문이 기록만 한다 |

관문은 시트를 읽은 결과를 캐시에 담아 두지만, **사람이 시트를 편집하면 편집 감지 트리거가 캐시를 비운다**(`apps-script/Triggers.js`). 메뉴 작업([세션ID 생성]·[출석부 변환]·[영상 매칭]) 뒤에도 자동으로 비워진다. 반영이 안 된 것 같으면 메뉴의 **[캐시 비우기]**를 실행한다.

**"즉시"는 다음 접속 기준이다.** 화면은 로그인 직후 자료를 한 번 받아 두므로(`docs/decisions.md` 2절),
이미 열려 있는 화면은 새로고침하거나 다시 로그인해야 바뀐 내용이 보인다.

「일정」 탭에 행을 추가했다면 해당 프로그램의 [세션ID 생성]을 실행해야 한다. 세션ID가 없으면 「자료」와 연결되지 않는다.

## 13. 학생ID (동명이인 구분)

「참여자」 탭은 성명만으로 학생을 구분하므로, 동명이인이 있으면 검색·인물 상세 화면에서 서로 다른 학생의 이력이 하나로 합쳐진다. 이를 막기 위한 최소 장치다.

- **동명이인이 실제로 있는 경우에만** 적용한다. 대부분의 학생은 학생ID 없이 성명만으로 충분하다.
- 담당자가 동명이인을 발견하면: ① 공통 시트 「학생」 탭(3-9절)에 각각 다음 순번으로 학생ID를 수기 등록 → ② 그 학생이 등장하는 프로그램 시트의 「출석부」·「자료」 탭 행에 학생ID를 같이 기재.
- 학생ID는 **프로그램이 달라도 같은 학생이면 같은 값**이다. 그래서 명부는 공통 시트 한 곳에만 둔다.
- [출석부 변환] 메뉴가 「출석부」의 학생ID를 「참여자」 탭으로 그대로 옮긴다.
- 관문(`data` 응답)은 `participants[].studentId`·`materials[].studentId`를 그대로 내보내고, 검색은 이 값으로 동명이인을 구분해 목록으로 보여준다(`docs/api.md` 3-3절, `docs/screens.md` 8절).
- 학생ID는 **자동 생성하지 않는다.** 동명이인 발견 빈도가 낮아 세션ID 같은 자동화가 필요하지 않다고 판단함.
- 학생ID 값에 생년월일 등 개인정보를 담지 않는다. 순번만 쓴다(`docs/decisions.md` 5절 결정 이유 참조).
- [점검] 메뉴가 「학생」 탭의 학생ID 중복, 프로그램 시트의 「출석부」·「자료」에 적힌 학생ID가 「학생」 탭에 없는 경우(오타)를 찾아낸다.

## 14. 시트 ID 보관

관문이 프로그램 시트를 열려면 각 시트의 ID가 필요하다.

| Script Properties 키 | 값 |
|---|---|
| `SHEET_ID_WORKSHOP` | 워크숍 시트 ID |
| `SHEET_ID_MENTORING` | 심화 멘토링 시트 ID |
| `SHEET_ID_CAMP` | 겨울 심화캠프 시트 ID |

- 값은 Apps Script 편집기의 **프로젝트 설정 → 스크립트 속성**에서 직접 넣는다. 코드와 이 문서에는 쓰지 않는다(`CLAUDE.md` 보안 7).
- 실제 ID는 `docs/private/`에만 기록한다.
- ID를 넣은 뒤 편집기에서 `setupProgramSheets()`(`apps-script/Setup.js`)를 한 번 실행하면 세 시트에 탭·머리글·선택 목록이 만들어진다. 머리글을 손으로 치면 오타 하나로 관문이 오류 없이 빈 값을 읽으므로 이 함수를 쓴다. 이미 있는 탭은 건드리지 않는다.
- 공통 시트는 **지금 관문이 붙어 있는 기존 시트를 그대로 쓴다.** 새로 만들면 관문 프로젝트와 배포 주소가 바뀐다.
- 프로그램 시트는 관문 소유 계정이 만든 시트여야 한다. 관문은 소유 계정 권한으로 실행되므로(`executeAs: USER_DEPLOYING`), 프로그램 시트를 다른 사람과 공유하지 않아도 관문은 읽을 수 있다.
